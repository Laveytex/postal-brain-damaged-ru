# Публикация в Steam Workshop

Инструкция для автора. Предмет Мастерской содержит только готовый патчер (`ru_patch.exe`) и `README.txt`; игроки подписываются, Steam скачивает файлы, игрок запускает `ru_patch.exe` из папки Мастерской.

## Как игра работает с Workshop (важно прочитать)

- AppID **POSTAL: Brain Damaged — 1359980**. Мастерская у игры есть: https://steamcommunity.com/app/1359980/workshop/
- «Родные» моды игры — сцены, собранные во **встроенном редакторе** (платформа readycode) и загружаемые оттуда же (меню *Моды → Опубликовать моды*). Игра скачивает подписки и показывает их в *Моды → Играть в моды*.
- Наш предмет — **не** мод этого формата. Steam сам не фильтрует типы файлов, и загрузка через SteamCMD технически работает для любой игры с ISteamUGC, но **как игра отреагирует на чужой формат, без проверки неизвестно** (может не показать, может показать «Ошибка при загрузке мода» (LOC_MENU_ModLoadError)). Поэтому первая публикация — **скрытая** (`visibility 2`), см. ниже.
- Подписанные предметы Steam кладёт в `<библиотека Steam>\steamapps\workshop\content\1359980\<ID предмета>\` (библиотека — та, где установлена игра). Патчер оттуда сам находит игру. Резервные копии он делает в папке игры (`_ru_backup`), не в папке Мастерской — Steam перезаписывает её при обновлениях.

## Где взять SteamCMD

Только официальный, от Valve:

- архив: https://steamcdn-a.akamaihd.net/client/installer/steamcmd.zip
- описание: https://developer.valvesoftware.com/wiki/SteamCMD

Распакуй `steamcmd.exe` в `steam_workshop\steamcmd\` (папка в `.gitignore`) **или** укажи путь в переменной окружения `STEAMCMD` (файл или папку). При первом запуске SteamCMD сам докачает обновления.

> В папке SteamCMD после входа хранятся токены (`config\config.vdf`, `ssfn*`). Никогда не коммить её и не отправляй никому. Пароль скрипты нигде не сохраняют — его и код Steam Guard спрашивает сам SteamCMD.

## Что менять перед публикацией

| Что | Где |
|---|---|
| Текст страницы (BBCode) | `workshop_description_ru.txt` — подставляется в описание при каждой загрузке |
| Название | `workshop_item.vdf` → `title` |
| Видимость | `workshop_item.vdf` → `visibility`: `0` публичная, `1` друзья, `2` скрытая, `3` по ссылке |
| Описание изменений | спрашивается при запуске (или `changenote` в VDF, или `-ChangeNote "…"`) |
| Превью | `preview\preview.png` (сейчас заглушка; ≤ 1 МБ, лучше скриншот русского меню) |
| Workshop ID | `workshop_item.vdf` → `publishedfileid` (`0` = создать новую работу) |

Описание из VDF (`description`) — короткая версия на случай, если `workshop_description_ru.txt` удалён.

## Первая публикация

1. Собери патчер и положи его в `content\`:
   ```
   steam_workshop\prepare_workshop.bat --build
   ```
   (`--build` вызывает `..\build_exe.bat`; без него просто копируется уже собранный `..\dist\ru_patch.exe`.)
2. Проверь, что соберётся, ничего не загружая:
   ```
   steam_workshop\upload_workshop.bat -DryRun
   ```
3. Убедись, что в `workshop_item.vdf` стоят `"publishedfileid" "0"` и `"visibility" "2"` (скрытая).
4. Запусти `upload_workshop.bat`, введи описание изменений, Steam login, подтверди `y`. Пароль и Steam Guard спросит SteamCMD.
5. При успехе скрипт покажет ссылку на работу и **сам запишет её ID** в `workshop_item.vdf`. Закоммить этот файл — иначе следующий запуск создаст ещё одну работу.
6. Если Steam просит — прими соглашение Мастерской: https://steamcommunity.com/sharedfiles/workshoplegalagreement (без этого работа может оставаться невидимой).
7. **Проверка до открытия для всех:** подпишись на свою скрытую работу, дождись загрузки, проверь файлы (см. ниже), запусти `ru_patch.exe` оттуда, затем запусти игру и открой *Моды → Играть в моды* и *Установка модов*: нет ли ошибок и странного пункта в списке.
8. Если всё в порядке — поставь `"visibility" "0"` и запусти `upload_workshop.bat` ещё раз (это уже обновление), либо смени видимость на странице работы в Steam.

Если игра ругается на предмет — лучше не делать его публичным: удали работу на её странице в Steam и распространяй перевод через Руководство Steam со ссылкой на GitHub (см. ниже).

## Обновление существующей работы

1. Обнови перевод/патчер, пересобери: `prepare_workshop.bat --build`.
2. При необходимости поправь `workshop_description_ru.txt`, превью, `visibility`.
3. `upload_workshop.bat` → описание изменений → login. В `workshop_item.vdf` уже стоит ID, поэтому обновится существующая работа (скрипт пишет «ОБНОВЛЕНИЕ работы …»).

ID работы хранится только в `workshop_item.vdf` (`publishedfileid`). Если его потерять — возьми число из адреса страницы работы (`…filedetails/?id=ЧИСЛО`) и впиши обратно.

## Как проверить загруженные файлы

- Страница: `https://steamcommunity.com/sharedfiles/filedetails/?id=<ID>` — название, описание, превью, вкладка «Изменения».
- Файлы у подписчика: `<библиотека Steam>\steamapps\workshop\content\1359980\<ID>\` — там должны быть ровно `ru_patch.exe` и `README.txt`. Размер `ru_patch.exe` сверь с `..\dist\ru_patch.exe`.
- Скрытую работу видишь только ты (и можешь подписаться на неё сам).

## Если Workshop не подойдёт

Для русификаторов в Steam обычно используют **Руководство** (Guides) со ссылкой на релиз GitHub: оно не попадает в игровой список модов и не нарушает ожиданий игры. Текст `workshop_description_ru.txt` почти без изменений годится для руководства (шаги установки поменять на «скачай zip с GitHub»).

## Ограничения

- Мастерская не запускает и не устанавливает `ru_patch.exe` сама — игрок запускает его вручную.
- Отписка от работы не удаляет перевод (файлы игры уже изменены) — удаление через `ru_patch.exe` → 2 или проверку целостности.
- PyInstaller-exe иногда ловят ложные срабатывания антивирусов; ссылка на исходники есть в описании.
- Разработчик игры модерирует свою Мастерскую и может скрыть предмет не своего формата.
